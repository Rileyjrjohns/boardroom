# auth

Who the user is and whether the app is open to them: the account, the session, the app lock.

| Layer             | What                                                                                                                                                                                                                                                                                                                              | May import                                              |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| `domain/`         | `entities/` (`User`, `Session`), `value-objects/` (`EmailAddress`, `Credentials`), `policies/` (`appLock`, `sessionExpiry`)                                                                                                                                                                                                       | `core/domain`, its own files, no package                |
| `application/`    | `ports/` (`AuthSession`, `BiometricGate`), `session/` (the session guards and the rules shared by the other features: `requireSession`, `endSession`, `AppLock`, `confirmWithBiometrics`, `sessionPolicy`, `purgeCaches`), `use-cases/` (`SignIn`, `SignOut`, `RestoreSession`, `GetCurrentUser`, `EvaluateAppLock`, `UnlockApp`) | `domain`, `core`, its own files, no package             |
| `infrastructure/` | `HttpAuthSession` and its wire class (`dto/sessionDto.ts`), `SessionVault` (the session kept in the secure storage), `biometrics/` (`DeviceBiometricGate` over `ExpoLocalAuthentication`; the text of the prompt comes from outside)                                                                                              | `domain`, `application`, `core`, the packages it adapts |
| `presentation/`   | `screens/` (`SignInScreen`, `LockScreen`), `components/` (`SignOutDialog`, `SessionNotice`, `RestoreFailure`), `hooks/` (`useSignIn`, `useSignOut`, `useUnlockApp`, `useCurrentUser`), `session/` (`useRestoreSession`, `useSessionCheck`, `useSessionWatch`)                                                                     | `domain`, `application`, `core`, never `infrastructure` |

- `domain` and `application` are pure: they run in plain Node, with no package.
- The in-memory session and biometric gate of the development build are in `src/composition/dev/in-memory`: they need the simulated server.
- The intended dependency is on `core` only. Today `purgeCaches`, `requireSession` and the use cases that sign in or out import the `MeetingCache` and `DocumentCache` ports (the caches they empty when a session ends); the next step turns that into a port that `meetings` and `documents` implement.
- The app lock and the session expiry are decided here; the check on a timer and on the way back from the background is in `presentation/session`, and the root state it writes is in `src/composition/shell/state`.
