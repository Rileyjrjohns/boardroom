# documents

The documents of a meeting: opening one (from the cache or from the server), closing it, and keeping the screen protected while it is shown.

| Layer             | What                                                                                                                                                                                                                                                                                                                                                                                                | May import                                                                 |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `domain/`         | `value-objects/` (`DocumentLocation`, `Watermark`)                                                                                                                                                                                                                                                                                                                                                  | `core/domain`, `auth/domain`, `meetings/domain`, its own files, no package |
| `application/`    | `ports/` (`DocumentRepository`, `DocumentCache`, `ScreenProtection`), `ScreenProtectionCoordinator.ts`, `use-cases/` (`OpenDocument`, `CloseDocument`, `ObserveScreenCapture`)                                                                                                                                                                                                                      | `domain`, `core`, `auth`, `meetings`, its own files, no package            |
| `infrastructure/` | `HttpDocumentRepository` and its wire class (`dto/documentDto.ts`), `persistence/` (`SqliteDocumentCache` and the stored form of a document), the content on disk (`documentContent`, `storeDocumentContent`), `pdfSignature` (the first bytes of a PDF), `native/` (`NativeScreenProtection` over the local module, the loader of the module), `InMemoryDocumentCache`, `InMemoryScreenProtection` | `domain`, `application`, `core`, the packages it adapts                    |
| `presentation/`   | `screens/DocumentScreen.tsx`, `components/` (`SecureContent`, `PdfViewer`, `DocumentWatermark`, `DocumentErrorState`, `CaptureNotice`), `hooks/` (`useDocumentView`, `useScreenCaptureNotice`), `navigation/useOpenDocumentScreen.ts`                                                                                                                                                               | `domain`, `application`, `core`, never `infrastructure`                    |

- `domain` and `application` are pure: they run in plain Node, with no package.
- The `Document` entity is in `meetings/domain`, as the meeting holds its documents.
- The in-memory repository of the development build and the PDF writer of the demo documents are in `src/composition/dev`.
- The watermark reads the `User` of `auth`. `SecureContent` is the one component that imports the secure view of the local native module, and `PdfViewer` the one that imports `react-native-pdf` (lint rules).
- `SqliteDocumentCache` reads the names of the tables from `src/composition/persistence/schema.ts`.
- The intended dependencies are `core`, `auth` and `meetings`. Today the document screen also imports the tones of the badges from `meetings/presentation`.
