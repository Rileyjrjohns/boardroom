# documents

The documents of a meeting: opening one (from the cache or from the server), closing it, and keeping the screen protected while it is shown.

| Layer             | What                                                                                                                                                                                                                                                                                                                                                                                                                                 | May import                                                                  |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------- |
| `domain/`         | `value-objects/` (`DocumentLocation`, `Watermark`), `errors/ScreenProtectionError.ts`                                                                                                                                                                                                                                                                                                                                                | `core/domain`, `auth/domain`, `meetings/domain`, its own files, no package  |
| `application/`    | `ports/` (`DocumentRepository`, `DocumentCache`, `ScreenProtection`), `ScreenProtectionCoordinator.ts`, `DocumentCachePurger.ts` (the `SessionDataPurger` of `auth` for the cached documents), `DocumentCacheEvictor.ts` (the `MeetingDocumentEvictor` of `meetings`), `retryableCodes.ts` (the codes of this feature that a second try can fix), `use-cases/` (`OpenDocument`, `CloseDocument`, `ObserveScreenCapture`)             | `domain`, `core`, `auth`, `meetings`, its own files, no package             |
| `infrastructure/` | `HttpDocumentRepository` and its wire class (`dto/documentDto.ts`), `persistence/` (`SqliteDocumentCache`, the stored form of a document, and the tables it owns `schema.ts`), the content on disk (`documentContent`, `storeDocumentContent`), `pdfSignature` (the first bytes of a PDF), `native/` (`NativeScreenProtection` over the local module, the loader of the module), `InMemoryDocumentCache`, `InMemoryScreenProtection` | `domain`, `application`, `core`, the packages it adapts                     |
| `presentation/`   | `screens/DocumentScreen.tsx`, `components/` (`SecureContent`, `PdfViewer`, `DocumentWatermark`, `DocumentErrorState`, `CaptureNotice`), `hooks/` (`useDocumentView`, `useScreenCaptureNotice`), `services/DocumentsServices.tsx`, `i18n/documentMessageKeys.ts`, `navigation/useOpenDocumentScreen.ts`, `testIds.ts`                                                                                                                 | `domain`, `application`, `core`, `auth`, `meetings`, never `infrastructure` |

- `domain` and `application` are pure: they run in plain Node, with no package.
- The `Document` entity is in `meetings/domain`, as the meeting holds its documents, and so is the wire form of a listed document. The document of this feature is what is opened: its location, its watermark, its content.
- The in-memory repository of the development build and the PDF writer of the demo documents are in `src/composition/dev`.
- The watermark reads the `User` of `auth`. `SecureContent` is the one component that imports the secure view of the local native module, and `PdfViewer` the one that imports `react-native-pdf` (lint rules).
- `documents` depends on `core`, `auth` and `meetings`: the screen of a document reuses the badge tones of `meetings/presentation`, and `DocumentCacheEvictor` implements a port that `meetings` declares. Nothing in `meetings` or `auth` imports this feature.
- `SqliteDocumentCache` reads the names of its tables from `infrastructure/persistence/schema.ts`, the slice of the schema that `documents` owns.
