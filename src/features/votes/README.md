# votes

Casting a vote on a resolution, keeping it in the outbox while the device is offline, and sending it when the connection is back.

| Layer             | What                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | May import                                                                  |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `domain/`         | `entities/` (`Vote`, `OutboxVote`: pending or rejected), `policies/votingEligibility.ts`, `withVoteRecorded.ts` (a meeting with a vote recorded on its resolution), `errors/` (`VotingError`, `VoteDeliveryError`)                                                                                                                                                                                                                                                                                                                                                                                                                                | `core/domain`, `auth/domain`, `meetings/domain`, its own files, no package  |
| `application/`    | `ports/` (`VoteRepository`, `VoteOutbox`, `RecordedVoteSink`), `use-cases/` (`CastVote`, `SyncPendingVotes`, `ListPendingVotes`, `AcknowledgeRejectedVote`, `DiscardUnreadableVotes`)                                                                                                                                                                                                                                                                                                                                                                                                                                                             | `domain`, `core`, `auth`, `meetings`, its own files, no package             |
| `infrastructure/` | `HttpVoteRepository` and its wire class (`dto/voteDto.ts`), `rejectionSchemas.ts` (how the rejection of a vote is written on the wire and in the outbox), `persistence/` (`SqliteVoteOutbox` and the tables it owns `schema.ts`), `InMemoryVoteOutbox`                                                                                                                                                                                                                                                                                                                                                                                            | `domain`, `application`, `core`, the packages it adapts                     |
| `presentation/`   | `screens/PendingVotesScreen.tsx`, `components/` (`ResolutionVoting`, `VoteDialog`, `OutboxVoteRow`, `AcknowledgeButton`, `UnreadableVotesNotice`, `SyncSummaryNotice`), `hooks/` (`resolutionVote`, `useResolutionVotes`, `useCastVote`, `usePendingVotes`, `useAcknowledgeRejectedVote`, `useDiscardUnreadableVotes`, `useRefreshQueries`), `slots/voteResolutionActions.tsx` (the implementation of the slot of `meetings`), `state/voteSyncStore.tsx`, `services/VotesServices.tsx`, `query/votesQueryKeys.ts`, `session/useVoteSync.ts`, `navigation/useOpenPendingVotes.ts`, `i18n/` (`voteMessageKeys.ts`, `voteMessages.ts`), `testIds.ts` | `domain`, `application`, `core`, `auth`, `meetings`, never `infrastructure` |

- `domain` and `application` are pure: they run in plain Node, with no package.
- The in-memory repository of the development build is in `src/composition/dev/in-memory`: it reads the simulated server.
- `votes` depends on `core`, `auth` and `meetings`. A vote is cast on a resolution of a meeting, so the `Meeting`, the `Resolution` and the `VoteChoice` are imported from `meetings`; `meetings` never imports this feature.
- Two links go through the composition. The cached copy of a meeting must show a vote the server recorded: `CastVote` and `SyncPendingVotes` call the `RecordedVoteSink` port, and `MeetingCacheVoteRecorder` (in `src/composition/glue`) implements it with `withVoteRecorded` over the `MeetingCache`. And the detail of a meeting offers the vote under each resolution: `VOTE_RESOLUTION_ACTIONS` implements the slot that `meetings` declares, and the composition plugs it in.
- `SqliteVoteOutbox` reads the names of its tables from `infrastructure/persistence/schema.ts`, the slice of the schema that `votes` owns.
