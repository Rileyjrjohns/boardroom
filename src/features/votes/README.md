# votes

Casting a vote on a resolution, keeping it in the outbox while the device is offline, and sending it when the connection is back.

| Layer             | What                                                                                                                                                                                                                                                                                                                                                                                                          | May import                                                                 |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `domain/`         | `entities/` (`Vote`, `OutboxVote`: pending or rejected), `policies/votingEligibility.ts`                                                                                                                                                                                                                                                                                                                      | `core/domain`, `auth/domain`, `meetings/domain`, its own files, no package |
| `application/`    | `ports/` (`VoteRepository`, `VoteOutbox`), `recordVoteInCache.ts` (a vote the server recorded, written into the cached meeting), `use-cases/` (`CastVote`, `SyncPendingVotes`, `ListPendingVotes`, `AcknowledgeRejectedVote`, `DiscardUnreadableVotes`)                                                                                                                                                       | `domain`, `core`, `auth`, `meetings`, its own files, no package            |
| `infrastructure/` | `HttpVoteRepository` and its wire class (`dto/voteDto.ts`), `rejectionSchemas.ts` (how the rejection of a vote is written on the wire and in the outbox), `persistence/SqliteVoteOutbox.ts`, `InMemoryVoteOutbox`                                                                                                                                                                                             | `domain`, `application`, `core`, the packages it adapts                    |
| `presentation/`   | `screens/PendingVotesScreen.tsx`, `components/` (`ResolutionVoting`, `VoteDialog`, `OutboxVoteRow`, `AcknowledgeButton`, `UnreadableVotesNotice`), `hooks/` (`resolutionVote`, `useResolutionVotes`, `useCastVote`, `usePendingVotes`, `useAcknowledgeRejectedVote`, `useDiscardUnreadableVotes`, `useRefreshQueries`), `session/useVoteSync.ts`, `navigation/useOpenPendingVotes.ts`, `i18n/voteMessages.ts` | `domain`, `application`, `core`, never `infrastructure`                    |

- `domain` and `application` are pure: they run in plain Node, with no package.
- The in-memory repository of the development build is in `src/composition/dev/in-memory`: it reads the simulated server.
- The intended dependencies are `core`, `auth` and `meetings`. Today the hook that tells the vote state of a resolution reads the current user from `auth/presentation`.
- `SqliteVoteOutbox` reads the names of the tables from `src/composition/persistence/schema.ts`.
- `withVoteRecorded` (a meeting with the vote recorded on its resolution) is still in `meetings/domain/entities/Meeting.ts`; it is to move here, with `RecordedVoteSink` as the port `CastVote` and `SyncPendingVotes` use.
