# core

The shared kernel: what every feature uses and no feature owns. It holds no business rule of a feature (a meeting, a vote, a session): those are in `features/`.

It has the same layers as a feature, with the same rules:

| Folder            | What                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | May import                                                      |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------- |
| `domain/`         | `shared/` (`Result`, `Brand`, the stable constants, the validation helpers), `errors/` (`AppError`, the open base every error extends, and the three families that several features share: `RepositoryError`, `StorageError`, `ValidationError`; the families of one feature are in that feature), `value-objects/` (the ids, `Instant`, `Duration`, `Page`, `PageCursor`, `PageRequest`), `policies/cacheAge.ts`                                                                                                                                                                                                                                                        | its own files, no package                                       |
| `application/`    | `ports/` (`Clock`, `Monitoring`, `Connectivity`, `SessionGate` (what the offline policy asks of whoever owns the session), and `ports/types/` for `CacheEntry`, `SessionRefusal` and `Unsubscribe`), `offline/` (`loadWithCacheFallback`, `Loaded`, `CacheResource`), `use-cases/ObserveConnectivity.ts`, `retryableCodes.ts` (`coreRetryableCodes`: the codes of the core that a second try can fix; each feature adds its own)                                                                                                                                                                                                                                         | `domain`, its own files, no package                             |
| `infrastructure/` | the adapters and the machinery that no feature owns, in the folders of the table below                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | `domain`, `application`, the packages it adapts                 |
| `presentation/`   | the shared interface: `components/` (buttons, dialogs, states, banners, fields, the privacy cover), `theme/` (the design tokens), `i18n/` (the setup, the resources, the typed keys of the core: `translationKeys.ts`), `query/` (the query client, which takes the policies it needs as arguments, and its conventions), `state/` (the interface store and the action epoch), `services/` (`CoreServices`: the ports that a shared component needs), `errors/` (`ErrorCatalog`: the context that tells the text of an error code, filled by the composition), `format/`, `accessibility/`, `platform/`, `navigation/` (the routes, the focus of a screen), `testIds.ts` | `domain`, `application`, `presentation`, never `infrastructure` |

- `domain` and `application` are pure: they run in plain Node (the `core` project of Jest, which is not this folder), with no package. Production code there never throws and never reads the system clock (lint rules).
- The kernel imports no feature and not `src/composition`, which is a lint error (the graph is in [`docs/architecture.md`](../../docs/architecture.md)). Where the kernel needs something that a feature owns, it declares the port, the context or the argument, and the composition fills it: the offline policy asks a `SessionGate` (implemented by `AuthSessionGate`), the query client takes the `isSessionEndingCode` policy and the retry codes it is given, the shared components read their services from `CoreServices` and the text of an error from `ErrorCatalog`, and the typed keys, test ids and query keys of a feature are in that feature.

Folders of `infrastructure/`:

| Folder            | What                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `shared/`         | `attempt` (work that settles in bounded time), `serialQueue`, `subscribers`, `results`, `sha256`, `valid`, `clonePlain`, the paths of the flaws of a body                                                                                                                                                                                                                                                                                        |
| `clock/`          | `SystemClock`, `sleep`                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `monitoring/`     | `ConsoleMonitoring`, and `SentryMonitoring` (the one file that imports the crash reporter)                                                                                                                                                                                                                                                                                                                                                       |
| `http/`           | the constants of the API (`protocol`), the client (`HttpClient`: the one module that calls `fetch`), the gateway errors, the checks of an answer, and `dto/wire.ts`; the schemas of a resource and the HTTP adapters of the remote ports are in the feature                                                                                                                                                                                      |
| `persistence/`    | the machinery of the encrypted local database: the opener (`DatabaseOpener`, `ExpoSqliteOpener`), the key (`databaseKey`, `randomKey`), `unlockDatabase`, `localDataReset`, `protectedDatabase`, the guards (`guarded`), `migrate`. It knows no table: each feature declares the tables it owns (`infrastructure/persistence/schema.ts`), and `src/composition/persistence` holds the history of the file (`migrations.ts`) and the whole schema |
| `files/`          | `FileStore` over a `FileVolume`, and the volume of a device (`ExpoFileVolume`)                                                                                                                                                                                                                                                                                                                                                                   |
| `secure-storage/` | `SecureStorage`, the keychain of the device, and `ExpoSecureStorage`                                                                                                                                                                                                                                                                                                                                                                             |
| `connectivity/`   | `ExpoConnectivity` over `ExpoNetworkState`; the simulated one is in `src/composition/dev/in-memory`                                                                                                                                                                                                                                                                                                                                              |
| `testing/`        | test support: the Node engines and doubles of the device (`NodeSqlite`, `NodeFileVolume`, `MemorySecureStorage`, `sleep`...). Only tests import it                                                                                                                                                                                                                                                                                               |

The architecture, the layout and the rules that the linter enforces are in [`docs/architecture.md`](../../docs/architecture.md).
